


## 一、项目开发背景

在数字经济快速发展的当下，智能手机、平板电脑、智能手表、蓝牙耳机、游戏主机、数码配件等电子产品已经成为大众刚需消费品。热门旗舰数码产品往往采用**限量发售、定时抢购**的销售模式，供需缺口大、抢购热度极高。

传统线下抢购存在**排队耗时、秩序混乱、黄牛囤货、信息不透明**等问题；普通线上商城又存在抢购规则简陋、无专属活动管理、用户数据散乱、商品管控缺失、后台统计薄弱等短板，无法满足专业化、规范化的数码产品限时抢购运营需求。

同时，针对高校计算机相关专业毕业设计、课程设计、实训项目，市面上急需**业务完整、技术主流、文档配套齐全、可直接部署运行**的 SpringBoot\+Vue 实战项目。

基于以上市场需求与教学实训需求，本次开发**基于 SpringBoot 与 Vue 的数码产品抢购系统**，采用前后端分离模式，搭建用户抢购前台 \+ 商家入驻 \+ 管理员运营后台的完整体系，实现数码商品上架、分类管理、限时秒杀抢购、订单流转、资讯发布、权限管控、数据统计全流程闭环。

## 二、项目开发目的与意义

### 2\.1 开发目的

1. 搭建专业化数码产品线上抢购平台，实现定时限量秒杀，规范抢购流程，杜绝恶意抢购乱象；

2. 实现商家入驻、商品发布、管理员审核管控一体化运营模式；

3. 为普通用户提供便捷的商品浏览、分类检索、限时抢购、订单管理、资讯查阅服务；

4. 为后台管理人员提供用户、商家、商品、抢购活动、资讯、系统配置的可视化管理能力；

5. 完成一套技术栈主流、结构规范、可用于毕设答辩、课程作业、二次开发的完整项目。

### 2\.2 开发意义

1. **业务意义**：降低数码抢购运营人工成本，提升商品管理、活动管理、订单管理效率，实现数字化、线上化运营；

2. **用户意义**：用户可随时随地通过浏览器参与抢购，查看活动预告、商品参数、抢购记录，购物体验更便捷公平；

3. **学习意义**：基于 SpringBoot\+Vue\+MySQL 企业级技术栈，涵盖前后端分离、接口开发、权限控制、秒杀业务、数据库设计等核心知识点，适合学习与求职面试项目简历使用；

4. **教学意义**：配套完整万字设计文档、源码、数据库脚本、部署教程，可直接作为高校课程设计、毕业设计参考项目。

## 三、系统技术栈详细介绍

### 3\.1 后端技术栈

1. **核心框架：SpringBoot**
简化 Spring 繁琐配置，自动内置 Tomcat 容器，一键启动项目，提供自动配置、依赖管理、事务控制、全局异常处理，快速开发 RESTful 风格接口。

2. **MVC 框架：SpringMVC**
负责请求分发、参数绑定、接口路由、视图跳转、统一结果返回，承接前端所有 HTTP 请求。

3. **持久层框架：MyBatis / MyBatis\-Plus**
轻量级 ORM 框架，简化 SQL 编写；MyBatis\-Plus 自带通用 CRUD、分页插件、条件构造器，大幅减少重复代码开发。

4. **数据库：MySQL 5\.7 / 8\.0**
开源关系型数据库，稳定性高、易于维护、支持事务与索引，适合存储用户、商家、商品、分类、抢购活动、订单、资讯等结构化数据。

5. **项目构建工具：Maven**
统一管理项目 Jar 包依赖、版本控制、项目编译、打包与部署，标准化项目结构。

6. **安全认证技术：JWT 令牌**
实现无状态登录认证，用户登录后生成 Token，请求接口携带令牌完成身份校验与权限拦截，无需频繁查询会话。

7. **辅助技术**
全局跨域配置、拦截器权限校验、分页插件、全局统一返回结果封装、日志记录、事务管理、防止超卖简易逻辑处理。

### 3\.2 前端技术栈

1. **核心框架：Vue**
渐进式前端开发框架，采用组件化、模块化开发，支持双向数据绑定，页面复用性高、维护简单。

2. **路由工具：Vue Router**
实现前端页面无刷新跳转、路由守卫、页面权限控制，区分登录 / 未登录访问权限。

3. **状态管理：Vuex**
管理全局共享数据，如用户登录信息、头像、权限状态，实现多组件数据共享。

4. **UI 组件库：Element UI/Element Plus**
提供表单、表格、弹窗、分页、导航、菜单等现成组件，快速搭建后台管理系统与用户商城页面，界面美观规范。

5. **网络请求：Axios**
封装 HTTP 请求，统一处理请求头、Token 携带、响应拦截、错误提示，对接后端所有 API 接口。

6. **可视化图表：ECharts**
绘制柱状图、折线图、饼图，实现商品销量统计、抢购活动参与人数、用户增长数据可视化展示。

### 3\.3 系统架构模式

整体采用**B/S 架构（浏览器 / 服务器模式）** \+ **前后端分离架构**

- 后端：只提供 API 接口，不负责页面渲染，专注业务逻辑、数据库操作、权限控制、抢购业务处理；

- 前端：独立开发页面，通过 Axios 调用后端接口，完成数据渲染与交互；

- 优势：前后端并行开发、解耦性强、维护方便、可适配 PC 端浏览器，无需安装客户端。

## 四、系统总体功能结构

本系统整体分为**三大角色**：**普通注册用户**、**入驻商家**、**系统管理员**，每个角色拥有独立权限与功能模块。

### 4\.1 管理员核心功能模块

#### 1\. 用户信息管理

- 查看全站所有注册用户列表，分页展示、条件模糊查询；

- 查看用户昵称、账号、手机号、注册时间、状态；

- 编辑用户资料、禁用 / 启用用户账号、重置用户登录密码；

- 查看用户抢购记录与历史订单，管控平台用户行为。

#### 2\. 入驻商家管理

- 商家入驻申请审核、商家信息列表管理；

- 新增、编辑、删除商家资料，包含商家名称、经营范围、联系方式、入驻时间；

- 冻结违规商家、恢复正常权限，控制商家商品上架权限；

- 统计各商家商品数量与销量数据。

#### 3\. 商品分类管理

- 支持一级分类、二级分类层级管理；

- 适配数码行业分类：手机通讯、平板设备、智能穿戴、耳机影音、游戏数码、数码配件等；

- 实现分类新增、编辑名称、排序调整、启用 / 隐藏分类、删除无用分类；

- 分类绑定对应数码商品，规范前台商品归类展示。

#### 4\. 数码商品信息管理

- 平台自营数码商品后台上架、编辑、下架、删除；

- 审核商家提交上架的数码商品，审核通过才可前台展示；

- 录入商品名称、品牌、价格、原价、库存、商品封面图、详情图文、规格参数；

- 管控违规商品、过期商品、缺货商品下架处理。

#### 5\. 限时抢购活动管理（核心业务）

- 新建抢购活动：设置活动名称、活动开始时间、结束时间、活动封面；

- 绑定参与抢购的数码商品，设置**抢购限量库存、单人限购数量**；

- 活动状态管理：未开始、进行中、已结束、暂停活动；

- 查看每场活动参与人数、抢购成功数量、剩余库存、成交金额统计；

- 支持活动提前结束、复制历史活动快速创建新活动。

#### 6\. 商城资讯公告管理

- 发布数码新品资讯、抢购活动预告、产品测评、平台规则公告；

- 资讯新增、编辑、删除、前台置顶、设置发布状态；

- 资讯分类管理，便于用户前台分类查阅。

#### 7\. 系统配置管理

- 后台管理员账号添加、密码修改、角色权限分配；

- 网站首页轮播图上传、切换、下架管理；

- 网站基础信息配置：网站名称、logo、底部版权、客服联系方式；

- 系统操作日志查看，记录管理员关键操作行为，保障系统安全。

#### 8\. 数据统计中心

- 用户数量统计、新增用户趋势图；

- 数码商品销量统计、各类别商品占比；

- 抢购活动参与热度、成交数据统计；

- 支持图表可视化展示与数据查看。

### 4\.2 普通用户前台功能模块

#### 1\. 注册与登录功能

- 账号密码注册、表单校验；

- 账号密码登录，JWT 令牌保持登录状态；

- 未登录限制参与抢购、下单、查看订单等核心操作。

#### 2\. 系统首页

- 首页轮播广告图展示；

- 热门数码商品推荐、新品上架专区；

- 即将开始的抢购活动预告入口；

- 最新商城资讯、平台公告展示。

#### 3\. 商品浏览与检索

- 按商品分类逐级浏览全部数码产品；

- 支持关键词搜索商品名称、品牌；

- 按价格区间、销量高低进行筛选排序；

- 查看商品详情、规格参数、商品图片、价格与库存状态。

#### 4\. 限时秒杀抢购

- 独立抢购专场页面，分区展示：即将开始、正在抢购、已结束；

- 定时开启抢购，活动开始后可限量下单；

- 系统限制单人限购数量、超库存无法下单，模拟真实电商秒杀逻辑；

- 抢购成功自动生成待付款订单。

#### 5\. 个人订单管理

- 全部订单、待付款、待发货、已完成、已取消订单分类查看；

- 查看订单编号、下单时间、商品信息、价格、订单状态；

- 支持未付款订单取消、查看订单详情。

#### 6\. 个人中心

- 修改个人昵称、头像、登录密码；

- 收货地址新增、编辑、设为默认、删除；

- 查看我的抢购记录、历史浏览商品、收藏商品。

#### 7\. 资讯阅读中心

- 浏览平台发布的数码资讯、抢购攻略、新品介绍、平台公告；

- 支持资讯列表浏览、详情全文查看。

### 4\.3 入驻商家功能模块

- 商家登录后台、个人资料维护；

- 提交数码商品上架申请，填写商品参数与图片；

- 查看自有商品审核状态、上下架管理；

- 查看自身商品订单、销量统计数据。

## 五、系统业务流程详细设计

### 5\.1 用户抢购业务流程

1. 用户进入系统 → 注册 / 登录账号；

2. 浏览首页或进入抢购专场，查看活动时间与参与商品；

3. 活动未开始：可预约、查看倒计时；

4. 活动开始：选择抢购商品，提交抢购订单；

5. 系统校验：是否登录、是否超出限购数量、是否还有库存；

6. 校验通过 → 生成待付款订单、扣减抢购库存；

7. 用户可查看个人订单，完成后续流程。

### 5\.2 商品上架审核流程

1. 商家登录后台 → 提交商品信息与图片；

2. 提交审核至管理员后台；

3. 管理员查看待审核商品 → 审核通过 / 驳回；

4. 审核通过：商品前台正常展示，可参与普通购买或抢购活动；

5. 审核驳回：退回商家并可填写驳回原因，商家修改后重新提交。

### 5\.3 抢购活动创建流程

1. 管理员进入抢购活动管理 → 新增活动；

2. 填写活动基础信息、设置起止时间；

3. 选择参与抢购的数码商品，设置限量库存、限购数量；

4. 保存发布活动，前台自动展示活动预告；

5. 到达开始时间自动开启抢购，结束时间自动关闭活动。

## 六、数据库设计概述

系统采用 MySQL 数据库，核心数据表包含：

1. 用户表：存储账号、密码、昵称、手机号、状态、注册时间；

2. 商家表：商家名称、联系方式、经营范围、审核状态；

3. 商品分类表：分类名称、父级分类、排序、状态；

4. 商品信息表：商品名称、品牌、价格、库存、封面图、详情、分类 ID、商家 ID、审核状态；

5. 抢购活动表：活动名称、时间、封面、活动状态；

6. 活动商品关联表：绑定活动与商品、抢购库存、限购数量；

7. 订单表：订单编号、用户 ID、商品信息、价格、订单状态、收货地址；

8. 资讯表：标题、封面、内容、发布时间、置顶状态；

9. 管理员表：账号、密码、角色、权限。

数据库遵循**三大范式**，合理设置主键、外键、索引，保证数据完整性与查询效率。
